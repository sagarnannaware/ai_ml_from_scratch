## 1. The RL Problem

### The setup

```
        ┌──────────────┐
        │    AGENT     │
        └──┬────────▲──┘
   action  │        │  state s_t, reward r_t
     a_t   ▼        │
        ┌─────────────┐
        │ ENVIRONMENT │
        └─────────────┘
```

At each timestep $t$: the agent observes state $s_t$, takes action $a_t$, receives reward
$r_{t+1}$, and transitions to $s_{t+1}$. The goal is to maximize **cumulative** reward, not
immediate reward.

### How RL differs from supervised learning

| | Supervised | Reinforcement |
|---|-----------|---------------|
| Signal | Correct label for every input | Scalar reward, often delayed and sparse |
| Data | Fixed i.i.d. dataset | Generated by the agent's own actions — **non-stationary** |
| Feedback | What you *should* have done | Only how good what you *did* was |
| Core difficulty | Generalization | **Exploration vs exploitation, credit assignment** |

Two problems define RL:

- **Credit assignment:** a reward arrives at step 100 — which of the previous 99 actions
  deserves the credit?
- **Exploration vs exploitation:** exploit known-good actions, or explore to find better ones?

### Terminology

| Term | Definition |
|------|-----------|
| **Agent** | The learner/decision-maker |
| **Environment** | Everything outside the agent |
| **State** $s\in\mathcal{S}$ | The situation; a sufficient statistic of history if Markov |
| **Observation** | What the agent actually sees (may be partial) |
| **Action** $a\in\mathcal{A}$ | A choice; discrete or continuous |
| **Reward** $r\in\mathbb{R}$ | Scalar feedback signal |
| **Policy** $\pi(a\mid s)$ | The agent's behaviour — a mapping from states to actions |
| **Return** $G_t$ | Cumulative discounted future reward |
| **Value** $V(s)$, $Q(s,a)$ | Expected return |
| **Model** | The agent's learned $P(s'\mid s,a)$ and $R(s,a)$, if any |
| **Episode / trajectory** | A sequence $s_0,a_0,r_1,\dots$ until termination |
| **On-policy** | Learns about the policy currently generating the data |
| **Off-policy** | Learns about a *different* policy than the one collecting data |

## 2. Markov Decision Processes

### Definition

An MDP is the tuple $\langle\mathcal{S},\mathcal{A},P,R,\gamma\rangle$:

| Element | Meaning |
|---------|---------|
| $\mathcal{S}$ | Set of states |
| $\mathcal{A}$ | Set of actions |
| $P(s'\mid s,a)$ | Transition probability |
| $R(s,a)$ | Expected immediate reward |
| $\gamma\in[0,1]$ | Discount factor |

**The Markov property:** the future depends only on the present state, not the history.

$$P(s_{t+1}\mid s_t, a_t) = P(s_{t+1}\mid s_t,a_t,s_{t-1},a_{t-1},\dots,s_0)$$

If this holds, the state contains everything needed for optimal decisions. When it doesn't (the
agent only sees partial observations), you have a **POMDP** — the usual fix is to stack recent
observations or use a recurrent policy.

### The return

$$G_t = r_{t+1} + \gamma r_{t+2} + \gamma^2 r_{t+3} + \cdots = \sum_{k=0}^{\infty}\gamma^k r_{t+k+1}$$

**Why discount?**
1. It guarantees a finite sum for infinite-horizon tasks.
2. It expresses a preference for sooner rewards.
3. It reflects genuine uncertainty about the far future.

| $\gamma$ | Behaviour |
|----------|-----------|
| 0 | Myopic — only the immediate reward matters |
| 0.9 | Effective horizon $\approx\frac{1}{1-\gamma} = 10$ steps |
| 0.99 | Horizon ≈ 100 steps — **the common default** |
| 1 | Undiscounted; valid only for episodic tasks |

### Reward design — where most RL projects fail

The reward function defines the problem completely. Get it wrong and the agent will optimize
exactly what you specified rather than what you meant (**reward hacking**). Classic examples: a
boat-racing agent that farms respawning bonus targets forever instead of finishing the race; a
cleaning robot that hides mess rather than removing it.

**Guidelines:** reward outcomes, not the actions you assume lead to them; keep it sparse but
add **potential-based shaping** when learning stalls
($F(s,s') = \gamma\Phi(s')-\Phi(s)$, which provably preserves the optimal policy); and always
watch a trained agent's actual behaviour rather than trusting the reward curve alone.

## 3. Value Functions and Bellman Equations

### The two value functions

**State-value function** — expected return from state $s$ following policy $\pi$:

$$V^\pi(s) = \mathbb{E}_\pi[G_t\mid s_t = s]$$

**Action-value (Q) function** — expected return from taking action $a$ in state $s$, then
following $\pi$:

$$Q^\pi(s,a) = \mathbb{E}_\pi[G_t\mid s_t=s, a_t=a]$$

The relationship: $V^\pi(s) = \sum_a\pi(a\mid s)Q^\pi(s,a)$.

**Advantage function** — how much better an action is than the average:

$$A^\pi(s,a) = Q^\pi(s,a) - V^\pi(s)$$

### The Bellman expectation equation

The key recursive insight: **the value of a state = immediate reward + discounted value of
where you land.**

$$V^\pi(s) = \sum_a\pi(a\mid s)\sum_{s'}P(s'\mid s,a)\big[R(s,a) + \gamma V^\pi(s')\big]$$

$$Q^\pi(s,a) = \sum_{s'}P(s'\mid s,a)\left[R(s,a) + \gamma\sum_{a'}\pi(a'\mid s')Q^\pi(s',a')\right]$$

### The Bellman optimality equation

The optimal policy takes the best action rather than averaging over a policy:

$$V^*(s) = \max_a\sum_{s'}P(s'\mid s,a)\big[R(s,a)+\gamma V^*(s')\big]$$

$$\boxed{Q^*(s,a) = \sum_{s'}P(s'\mid s,a)\left[R(s,a) + \gamma\max_{a'}Q^*(s',a')\right]}$$

**Once you have $Q^*$, the optimal policy is trivial:**

$$\pi^*(s) = \arg\max_a Q^*(s,a)$$

That boxed equation is the foundation of Q-learning and DQN — everything else is how to
estimate it.

**Existence and uniqueness:** the Bellman optimality operator is a $\gamma$-contraction in the
sup norm, so by the Banach fixed-point theorem it has a unique fixed point, and iterating it
converges to $V^*$ geometrically. That's the theoretical guarantee underpinning value iteration
and Q-learning.

## 4. Dynamic Programming

When you **know** $P$ and $R$ (a perfect model), you can solve the MDP exactly.

### Policy iteration

```
1. Initialize π arbitrarily
2. POLICY EVALUATION:
     repeat until convergence:
       V(s) ← Σ_a π(a|s) Σ_s' P(s'|s,a)[R + γV(s')]    for all s
3. POLICY IMPROVEMENT:
     π'(s) ← argmax_a Σ_s' P(s'|s,a)[R + γV(s')]
4. If π' == π, stop. Else π ← π' and go to 2.
```

**Policy improvement theorem:** acting greedily with respect to $V^\pi$ produces a policy at
least as good as $\pi$. Since there are finitely many deterministic policies and each iteration
strictly improves, policy iteration converges in finite steps.

### Value iteration

Merge evaluation and improvement into a single update:

$$V_{k+1}(s) \leftarrow \max_a\sum_{s'}P(s'\mid s,a)\big[R(s,a)+\gamma V_k(s')\big]$$

Simpler and usually faster in practice. Stop when $\max_s|V_{k+1}(s)-V_k(s)| < \epsilon$.

**Why DP isn't enough:** it requires knowing the environment's dynamics (rarely true), and it
sweeps over the entire state space (impossible when states number in the billions — chess has
$10^{47}$). RL exists to relax both requirements.

## 5. Monte Carlo and Temporal Difference Learning

### Monte Carlo

Learn from **complete episodes** by averaging the actual observed returns:

$$V(s_t) \leftarrow V(s_t) + \alpha\big[G_t - V(s_t)\big]$$

- ✅ Unbiased (uses real returns), needs no model, unaffected by violations of the Markov property.
- ❌ High variance, and requires episodes to *terminate* — no learning during an episode.

### Temporal Difference (TD) learning

**The central idea of RL: bootstrap.** Update toward an estimate rather than waiting for the
true return.

$$V(s_t) \leftarrow V(s_t) + \alpha\underbrace{\big[\overbrace{r_{t+1}+\gamma V(s_{t+1})}^{\text{TD target}} - V(s_t)\big]}_{\text{TD error }\delta_t}$$

- ✅ Learns online, from incomplete episodes, with much lower variance.
- ❌ Biased (the target uses a current estimate); requires the Markov property.

The **TD error** $\delta_t = r_{t+1}+\gamma V(s_{t+1}) - V(s_t)$ is a remarkably central
quantity — it even has a correspondence with dopamine signalling in the brain.

### The bias–variance spectrum

| Method | Target | Bias | Variance |
|--------|--------|------|----------|
| TD(0) | $r_{t+1}+\gamma V(s_{t+1})$ | High | Low |
| n-step TD | $r_{t+1}+\cdots+\gamma^nV(s_{t+n})$ | Medium | Medium |
| Monte Carlo | $G_t$ (full return) | None | High |

**TD($\lambda$)** interpolates smoothly across the whole spectrum using **eligibility traces**,
a weighted average of all n-step returns with weight $(1-\lambda)\lambda^{n-1}$.

### SARSA — on-policy TD control

$$Q(s_t,a_t)\leftarrow Q(s_t,a_t)+\alpha\big[r_{t+1}+\gamma Q(s_{t+1},a_{t+1}) - Q(s_t,a_t)\big]$$

Named for the tuple it uses: $(s,a,r,s',a')$. It learns the value of the policy it is *actually
following*, exploration included — which makes it more conservative near danger (the classic
cliff-walking example: SARSA learns the safe path away from the edge; Q-learning learns the
optimal path along it and falls off during exploration).

## 6. Q-Learning

📄 `reinforcement/q_learning_frozenlake_example.py`

**The most important classical RL algorithm.** Off-policy TD control.

$$\boxed{Q(s_t,a_t)\leftarrow Q(s_t,a_t)+\alpha\Big[r_{t+1}+\gamma\max_{a'}Q(s_{t+1},a') - Q(s_t,a_t)\Big]}$$

**Why off-policy:** the update uses $\max_{a'}Q(s',a')$ — the value of the *greedy* action —
regardless of which action the behaviour policy actually took. So the agent can explore
randomly while still learning the optimal policy.

### Algorithm

```
Initialize Q(s,a) arbitrarily (e.g. zeros); Q(terminal, ·) = 0
for each episode:
    s = env.reset()
    while not done:
        a = ε-greedy(Q, s)                        # behaviour policy
        s', r, done = env.step(a)
        Q[s,a] += α * (r + γ * max_a' Q[s',a'] - Q[s,a])
        s = s'
    decay ε
```

### Exploration strategies

**ε-greedy** — with probability $\varepsilon$ act randomly, otherwise greedily:

$$\pi(a\mid s) = \begin{cases}1-\varepsilon+\frac{\varepsilon}{|\mathcal{A}|} & a = \arg\max_a Q(s,a)\\ \frac{\varepsilon}{|\mathcal{A}|} & \text{otherwise}\end{cases}$$

Decay $\varepsilon$ over training (e.g. $1.0\to0.01$ exponentially): explore early, exploit late.

| Strategy | Idea |
|----------|------|
| **ε-greedy** | Simple, effective, the default |
| **Boltzmann/softmax** | $\pi(a\mid s)\propto e^{Q(s,a)/\tau}$ — probability proportional to value |
| **UCB** | $a = \arg\max_a\left[Q(s,a) + c\sqrt{\frac{\ln t}{N(s,a)}}\right]$ — optimism under uncertainty |
| **Thompson sampling** | Sample from a posterior over values |
| **Curiosity / intrinsic motivation** | Reward prediction error — essential for sparse-reward tasks like Montezuma's Revenge |

### Convergence
Q-learning converges to $Q^*$ with probability 1, provided every state–action pair is visited
infinitely often and the learning rate satisfies the Robbins–Monro conditions:

$$\sum_t\alpha_t = \infty, \qquad \sum_t\alpha_t^2 < \infty$$

### The limitation
A tabular $Q$ requires one entry per $(s,a)$ pair. FrozenLake (16 states × 4 actions) is fine.
Chess is not. **Function approximation** is the answer — and that means neural networks.

## 7. Deep Q-Networks

DQN (Mnih et al., 2015) achieved human-level play on Atari from raw pixels, launching modern
deep RL.

Replace the table with a network $Q(s,a;\theta)$ and minimize the TD error as a regression loss:

$$\mathcal{L}(\theta) = \mathbb{E}_{(s,a,r,s')\sim\mathcal{D}}\left[\Big(\underbrace{r+\gamma\max_{a'}Q(s',a';\theta^-)}_{\text{target}} - Q(s,a;\theta)\Big)^2\right]$$

### The two innovations that made it work

Naively combining Q-learning with neural networks diverges. Two fixes:

**1. Experience replay.** Store transitions $(s,a,r,s')$ in a buffer and train on random
minibatches. This breaks the temporal correlation between consecutive samples (which violates
the i.i.d. assumption SGD needs) and lets each experience be reused many times, improving sample
efficiency.

**2. Target network.** Compute the TD target with a separate network $\theta^-$, synced from
$\theta$ every $C$ steps. Without it, the target moves every time you update — you're chasing a
moving target, and the feedback loop diverges.

### Key improvements

| Variant | Fix |
|---------|-----|
| **Double DQN** | $\max$ over a noisy estimate is systematically **over-optimistic** (Jensen's inequality). Decouple selection from evaluation: $r+\gamma Q(s',\arg\max_{a'}Q(s',a';\theta);\theta^-)$ |
| **Dueling DQN** | Split into value and advantage streams: $Q(s,a)=V(s)+\big(A(s,a)-\frac{1}{\|\mathcal{A}\|}\sum_{a'}A(s,a')\big)$ — learns state values even when actions barely matter |
| **Prioritized replay** | Sample transitions in proportion to TD error — learn more from surprising events |
| **Noisy Nets** | Learnable noise in the weights replaces ε-greedy exploration |
| **Distributional (C51)** | Model the full return *distribution*, not just its mean |
| **Rainbow** | All of the above combined — much stronger than any single component |

**DQN's scope:** discrete action spaces only, because it needs $\max_a$ over actions.
Continuous control requires policy gradients or actor–critic methods (DDPG, TD3, SAC).

## 8. Policy Gradient Methods

Instead of learning values and deriving a policy, **learn the policy directly**:
$\pi_\theta(a\mid s)$.

### Why bother

- Naturally handles **continuous action spaces**.
- Can learn **stochastic** policies (necessary in partially observable settings, and in games
  where randomness is optimal — think rock-paper-scissors).
- Smooth policy changes → better convergence properties than value methods, which can flip
  policies discontinuously.

### The objective

$$J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta}\left[\sum_{t=0}^{T}\gamma^t r_t\right]$$

### The Policy Gradient Theorem

$$\nabla_\theta J(\theta) = \mathbb{E}_{\pi_\theta}\big[\nabla_\theta\log\pi_\theta(a\mid s)\,Q^{\pi_\theta}(s,a)\big]$$

**Derivation sketch (the log-derivative trick).** For a trajectory distribution
$p_\theta(\tau)$:

$$\nabla_\theta\mathbb{E}[R(\tau)] = \nabla_\theta\int p_\theta(\tau)R(\tau)d\tau = \int \nabla_\theta p_\theta(\tau)\,R(\tau)\,d\tau$$

Use the identity $\nabla_\theta p_\theta = p_\theta\nabla_\theta\log p_\theta$:

$$= \int p_\theta(\tau)\,\nabla_\theta\log p_\theta(\tau)\,R(\tau)\,d\tau = \mathbb{E}\big[\nabla_\theta\log p_\theta(\tau)R(\tau)\big]$$

Since $\log p_\theta(\tau) = \log p(s_0) + \sum_t\big[\log\pi_\theta(a_t\mid s_t) + \log P(s_{t+1}\mid s_t,a_t)\big]$
and the environment terms don't depend on $\theta$, they vanish under the gradient:

$$\nabla_\theta J = \mathbb{E}\left[\sum_t\nabla_\theta\log\pi_\theta(a_t\mid s_t)\,R(\tau)\right] \qquad \blacksquare$$

**The crucial consequence: you can compute the gradient without knowing the environment
dynamics.** That's what makes model-free RL possible.

**Intuition:** increase the log-probability of actions that led to high return; decrease it for
those that led to low return.

### REINFORCE

```
for each episode:
    generate trajectory τ following π_θ
    for each t:
        G_t = Σ_{k=t}^{T} γ^{k-t} r_k
        θ ← θ + α γ^t G_t ∇_θ log π_θ(a_t | s_t)
```

Unbiased but **extremely high variance** — the entire episode return scores every action in it.

### Variance reduction

**1. Baselines.** Subtract any function of state; it doesn't bias the gradient (because
$\mathbb{E}[\nabla_\theta\log\pi_\theta(a|s)] = 0$) but cuts variance dramatically:

$$\nabla_\theta J = \mathbb{E}\big[\nabla_\theta\log\pi_\theta(a\mid s)(Q(s,a) - b(s))\big]$$

The best practical baseline is $b(s) = V(s)$, giving the **advantage** $A(s,a) = Q(s,a)-V(s)$.
Now actions are scored by whether they beat the state's average, not by raw return.

**2. Actor–critic.** Learn both:
- **Actor** $\pi_\theta(a\mid s)$ — chooses actions.
- **Critic** $V_\phi(s)$ — estimates value, providing a low-variance advantage estimate.

$$A_t \approx r_t + \gamma V_\phi(s_{t+1}) - V_\phi(s_t)$$

**3. GAE (Generalized Advantage Estimation)** — an exponentially-weighted average of n-step
advantages that gives you an explicit bias/variance dial:

$$\hat A_t^{\text{GAE}(\gamma,\lambda)} = \sum_{l=0}^{\infty}(\gamma\lambda)^l\delta_{t+l}, \qquad \delta_t = r_t+\gamma V(s_{t+1})-V(s_t)$$

$\lambda=0$ → TD (low variance, biased); $\lambda=1$ → Monte Carlo (unbiased, high variance).
$\lambda\approx0.95$ is the standard.

### The algorithm family

| Algorithm | Type | Actions | Notes |
|-----------|------|---------|-------|
| **REINFORCE** | On-policy PG | Both | Simple, high variance |
| **A2C/A3C** | Actor–critic | Both | Parallel workers |
| **TRPO** | On-policy PG | Both | Trust region via a KL constraint; strong but complex |
| **PPO** | On-policy PG | Both | **The default** — TRPO's benefits, far simpler |
| **DDPG** | Off-policy AC | Continuous | Deterministic policy; brittle |
| **TD3** | Off-policy AC | Continuous | Twin critics + delayed updates fix DDPG's overestimation |
| **SAC** | Off-policy AC | Continuous | **Maximum entropy** — best sample efficiency for robotics |

**SAC's maximum-entropy objective** adds an entropy bonus, so the agent is rewarded for staying
stochastic — which improves exploration and robustness:

$$J(\pi) = \sum_t\mathbb{E}\big[r(s_t,a_t) + \alpha\mathcal{H}(\pi(\cdot\mid s_t))\big]$$

## 9. PPO (Proximal Policy Optimization)

The workhorse of modern RL — and the algorithm behind RLHF.

### The problem it solves
Policy gradient methods are destroyed by a single too-large update: the policy collapses and,
because it generates its own data, it never recovers. TRPO solved this with a hard KL
constraint requiring second-order optimization. **PPO gets 95% of the benefit with a first-order
clipped objective.**

### The clipped surrogate objective

Define the probability ratio between new and old policies:

$$r_t(\theta) = \frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{\text{old}}}(a_t\mid s_t)}$$

$$\boxed{L^{\text{CLIP}}(\theta) = \mathbb{E}_t\Big[\min\big(r_t(\theta)\hat A_t,\;\;\text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\hat A_t\big)\Big]}$$

with $\epsilon\approx0.2$.

**How the clipping works:** if an action was good ($\hat A_t>0$), increasing its probability
raises the objective — but only up to $r_t = 1+\epsilon$, past which the clipped term flattens
and there's **no further gradient incentive**. Symmetrically for bad actions at $1-\epsilon$.
The `min` makes the bound pessimistic, so the objective is a lower bound on the true
improvement. The net effect: the policy can't move far from where it collected its data in a
single update.

### Full objective

$$L = L^{\text{CLIP}} - c_1\underbrace{L^{VF}}_{\text{value loss}} + c_2\underbrace{\mathcal{H}[\pi_\theta]}_{\text{entropy bonus}}$$

The value loss trains the critic; the entropy bonus discourages premature convergence to a
deterministic policy.

### Algorithm

```
for iteration = 1, 2, ...:
    collect T timesteps from N parallel actors using π_θ_old
    compute advantages Â_t with GAE
    for epoch = 1..K:                     # K ≈ 4, reusing the same batch
        for minibatch in data:
            update θ by maximizing L^CLIP + value + entropy terms
    θ_old ← θ
```

Reusing each batch for several epochs is what makes PPO far more sample-efficient than vanilla
policy gradients — and the clipping is precisely what makes that reuse safe.

### PPO in RLHF

In [Module 06 §7](06_nlp_and_llms.md#7-alignment), the mapping is:

| RL concept | LLM equivalent |
|------------|---------------|
| State | The prompt + tokens generated so far |
| Action | The next token |
| Policy | The language model |
| Reward | The reward model's score on the completed response (+ a per-token KL penalty) |
| Reference policy | The SFT model, keeping the policy from drifting |

### Typical hyperparameters

| Parameter | Value |
|-----------|-------|
| `clip_epsilon` | 0.2 |
| `gamma` | 0.99 |
| `gae_lambda` | 0.95 |
| `epochs per batch` | 4–10 |
| `learning_rate` | $3\times10^{-4}$ (decaying) |
| `value_coef` | 0.5 |
| `entropy_coef` | 0.0–0.01 |

## 10. Practical RL

### Should you use RL at all?

**Honest answer: usually no.** RL is the right tool only when *all* of these hold:

1. The problem is genuinely **sequential** — actions affect future states.
2. You have a **simulator**, or can afford real-world exploration safely.
3. You can define a reward that actually captures what you want.
4. Supervised learning on logged/expert data (imitation learning) isn't sufficient.

If you have expert demonstrations, **behavioural cloning is a supervised problem and will
usually work better with far less pain.** If the decision is one-shot, use a bandit algorithm,
not full RL. If you can't simulate, look at **offline RL** — and be aware it's still hard.

### Why RL is hard

| Problem | Description |
|---------|-------------|
| **Sample inefficiency** | Millions of steps for tasks a human learns in minutes |
| **Instability** | Same code, same hyperparameters, different seed → wildly different results |
| **Reward hacking** | The agent optimizes what you specified, not what you meant |
| **Sim-to-real gap** | Works in simulation, fails on hardware |
| **Reproducibility** | Notoriously seed-sensitive; always report over ≥5 seeds |
| **Sparse rewards** | Random exploration may never encounter a reward at all |
| **Non-stationarity** | The data distribution changes as the policy changes |

### Debugging checklist

1. **Verify the environment first.** Random policy, then a hand-coded policy — do rewards look
   sane? Are episodes terminating when they should?
2. **Test on a solved environment.** CartPole should be solved in minutes. If your PPO can't
   solve CartPole, the bug is in your implementation, not your hyperparameters.
3. **Normalize** observations (running mean/std) and rewards. This matters far more in RL than
   in supervised learning.
4. **Check shapes and the discount.** Off-by-one on `done` handling — bootstrapping past a
   terminal state — is the single most common RL bug.
5. **Plot everything:** episode return, episode length, value loss, policy entropy, KL
   divergence between updates, gradient norms. **Entropy collapsing to 0 early** means
   premature convergence; **KL spiking** means your updates are too large.
6. **Run multiple seeds.** A single seed tells you almost nothing.

### Libraries
**Stable-Baselines3** (reliable reference implementations — start here), **CleanRL**
(single-file implementations, excellent for learning), **Gymnasium** (the environment API),
**PettingZoo** (multi-agent), **RLlib** (distributed scale), **TRL** (RLHF for language models).
